# Repository audit remediation — 24 September 2026

The source audit at commit `e0d3a23` is a release-blocking assessment, not a public-release approval. This document records what the following working-tree changes address. A passing test suite does not replace native failure-path acceptance or an independent security review.

| Finding | Current code change | Still required |
| --- | --- | --- |
| B01 iOS Spark secret logs | Pinned SDK 0.7.12 Swift `print` calls are removed by a strict postinstall patch and checked in the local verification gate. | Build and inspect the actual iOS release artifact and logs. Review again on every SDK update. |
| B02 Bitcoin withdrawal recovery | Known pre-submission authorization/quote failures become `aborted`; a leftover `prepared` record is released on reconciliation. Provider `FAILED`/`EXPIRED` states are terminal. Unknown submissions remain blocked. | Reconstruct operations after seed restore; test process death at every transition against the native SDK. |
| B03 Bitcoin deposit claim | Authorization loss before SDK entry restores `action_required` without a claim call. | Native process-death and terminal claim-error tests; comprehensive restore. |
| B04 inaccessible SecureStore key | Recovery from an unreadable key now checks the full mnemonic against a saved SecureStore wallet identity (or matching saved backup identity) and requires device authentication. It never replaces a readable key. | Native biometrics-change tests. Older installations with neither identity record cannot be matched safely and remain blocked. |
| B05 duplicate direct HBAR payment | An unresolved direct HBAR payment from the same payer account now blocks a second direct transaction ID before submission. Once a final result is recorded, a new payment is allowed. | Introduce wallet/network-scoped payment intents and a deliberate resolution flow. |
| B06 Hedera journal eviction | All unresolved records are retained; only settled history is trimmed. A high pending-record ceiling fails before a new network submission. | Define archival/storage policy and test it on devices. |
| B07 failed Spark startup cleanup | The owned wallet instance disposes its connections if SDK initialization fails after polling starts. | Confirm cleanup on native Android and iOS builds under failed sync/retry. |
| B08 hanging Spark transport | The pinned SDK patch bounds each XHR. `SessionResource` now has a 75-second visible startup deadline, cancellation signal and late-result cleanup while keeping one key-bearing SDK startup in its ownership queue. | Spark SDK 0.7.12 does not expose cancellation for every native startup/signer operation. If one such call never settles, safe automatic retry is still blocked rather than starting a parallel secret-bearing instance. |
| B09 Bitcoin restore discovery | Historical and head withdrawal searches remain separate. Prepare **and** Submit check the provider head, merge new requests, and recheck the latest first page before allowing a send after a multi-page scan. Unresolved or incomplete status blocks signing and withdrawal. | The SDK does not offer an atomic, cross-device payment intent. Provider page ordering/cursor stability and real restore must be validated; concurrent sends after the last check are not prevented across devices. Unknown historical recipient and amount are not invented. |
| B10 Bitcoin provider pagination | Separate durable cursors continue historical withdrawal restore, unresolved-withdrawal lookup, claim lookup, and static-deposit address/UTXO scans across polls and restarts. Each page is committed only after matching records are saved. Explicit bounds fail visibly instead of implying completeness. | Verify the provider's real page ordering and cursor stability on native builds, including changed address lists and long histories. |
| B11 duplicate Hedera key accounts | Security lists exact on-network key matches from paginated Mirror results, lets the user choose or enter a numeric account ID, and rechecks the key before binding. Foreign continuation URLs and incomplete large result sets fail visibly. | Native test with multiple matching Mainnet accounts; the account list may be cached by Mirror Node. |
| B12 Hedera UNKNOWN status | Empty, `UNKNOWN`, and `FUTURE_VALUE` Mirror results remain pending. | Validate more Mirror response shapes in native integration. |
| B13 Hedera checkout history | Mirror history queries include `CONTRACTCALL` and child transfers. When both carry an account delta, the parent is preferred so its fee is retained, including when the parent arrives on a later history page; a synthetic cross-page regression test covers this. | Validate real checkout parent/child deltas, fees, and cross-page deduplication against Mainnet samples. |
| B14 native HTTP redirects | Payment JSON, Hedera Mirror, and Bitcoin deposit verification now use Expo's native fetch with `redirect: 'error'`; its Android OkHttp and iOS URLSession implementations stop the redirect before following it. | Verify on Android/iOS release builds and repeat the source review when Expo changes. SDK-owned network transports are separate. |
| B15 private URL literals | All literal IPv6, including mapped/link-local forms, and more IPv4 special ranges are treated as private in production. The app-owned fetch paths now reject redirects natively. | A DNS hostname that resolves to a private IP still needs resolution/connection-level enforcement; this is not closed. |
| B16 oversized HTTP responses | App-owned HTTP reads now check Content-Length and count streamed bytes before decoding, including when Content-Length is missing or false. | Native transport can briefly buffer data before the JavaScript reader starts; test actual memory behavior on devices. A transport-level byte cap would be stronger. |
| B17 address cache integrity | The Bitcoin static receive-address cache now uses device SecureStore. Legacy plaintext entries are ignored and removed on wallet wipe. | Native cache migration/fetch test and provider ownership review. |
| B18 partial wallet deletion | A durable wipe marker blocks unlock/new wallet while sequential idempotent deletion resumes on startup. MoonPay and legacy address-cache records are included. | Device interruption tests during every deletion step. |
| B19 payment journal scope | HBAR and Lightning v2 journals use explicit wallet public-key and network scopes in keys, documents and records. All app call sites use scoped adapters; late reconciliation cannot write into another wallet's scope, and wipe clears scoped and legacy keys. | Unscoped v1 pending records have no provable wallet/network owner. They remain untouched and block new sends; an explicit verified resolution or user-facing legacy recovery policy is still needed. They are never silently adopted or erased to unblock payments. |
| B20 exchange rates | Open screens refresh stale rates in the foreground and on app resume; the hook exposes a retry operation. | Device test for offline/reconnect and long-lived Send/Receive views. |
| B21 repeated deposit writes | Known UTXOs avoid writes; 100 new outputs are inserted in one SQLite transaction and repeated discovery uses indexed existing-ID checks. | Native device latency and long-running provider discovery still need validation. |
| B22 receive archive lifecycle | Authoritative failed requests become terminal; expired unresolved requests are retained but checked less often. Settled archive entries make room for new requests. A regression test verifies that a payment confirmed after expiry is recorded once on a later check. | Device test for delayed provider finalization and a separate long-term journal/archival policy. |
| B22 Bitcoin operation storage | Native operations now use indexed SQLite rows with bounded keyset history pages. A transactionally committed migration imports legacy AsyncStorage records before removing the old document; wipe preserves the migration marker so stale legacy data cannot reappear. Active checks and request-ID lookup no longer parse all settled rows. | Actual Android/iOS migration, database corruption handling and long-history performance remain untested on devices. Additional local encryption of payment metadata is B26. |
| B23 Hedera reconciliation queue | Mirror requests run outside the journal's storage queue with four-worker concurrency; results merge only into still-pending records. | Device latency and interruption tests. |
| B24 history rendering / N02 | The activity page remains a virtualized FlatList. SQLite performs bounded keyset pages with one UTF-16-consistent ID tie order; the pure store uses the same cursor order. | Long-history native scrolling and mixed provider IDs need device acceptance. |
| B25 LNURL endpoint latency | Bech32 LNURL endpoints are classified from one response. Validated LNURL metadata is reused for up to ten seconds across scan and preparation; OCP quotes are always loaded fresh. | Test amount selection and live LNURL/OCP servers; invoice amount and metadata proof remain validated before payment. |
| B27 notification privacy | Receive notifications omit payment amounts; amounts remain visible inside the unlocked app. | User preference and lock-screen review on Android/iOS. |
| B28/B29 quality and dependencies | Lint covers wallet logic, tests, demos, and scripts. Directly imported packages are declared and pinned in the lockfile. | Run `npm ci` from a clean online checkout and native dependency build. |
| R02/R03 release gate and versions | GitHub Actions runs a clean install and quality gate; EAS production/mainnet-candidate workers now run the same gate in the post-install hook. Production uses a remote version source and automatic build-number increment. | GitHub branch protection, EAS permissions/credentials, initial remote version synchronization and reviewer approval remain external. Custom EAS build workflows can bypass npm hooks unless they invoke the gate explicitly. |
| D01/D02 reference services | The Travel Rule demo reserves a proof before awaiting an invoice and checks its signed transaction reference against the configured merchant reference. The OCP demo bounds quote count and cleans expired quotes. | These local reference servers still lack durable replay storage, independent invoices per order, and production rate limits; do not expose them as payment services. |

**Open P1 release blockers:** native/independent acceptance R01 and the cross-device Bitcoin send design in B09. B04 is only safe for wallets with a saved identity. B08, legacy B19, B15/B16, B26, B30 and release/operations dependencies remain open. B01/B02/B03/B05/B07/B10/B11/B13 still need the acceptance or design work listed above. Do not use this working tree as a public release solely because the automated checks pass.

## Nachprüfung dieses Arbeitsauftrags

Der folgende Nachweis verwendet ausschließlich synthetische Wallets, Speicher und Providerantworten. `npm ci --offline` installierte 1.279 Pakete aus dem Lockfile und führte beide Spark-Postinstall-Patches aus. Kein Gerätetest oder nativer Release-Build wurde durchgeführt.
